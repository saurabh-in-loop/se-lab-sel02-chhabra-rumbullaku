# Decision Log

<!-- Records decisions made during Stakeholder Session 1, including subsequent clarifications. -->

| # | Decision | Answers | Date |
|---|---|---|---|
| D-01 | Booking guarantee | A booking is a promise to the guest. Overbooking is not allowed, and confirmed bookings must be guaranteed. | Stakeholder Session 1 |
| D-02 | Booking confirmation | Bookings are confirmed instantly after successful payment. Owner approval is not required. | Stakeholder Session 1 |
| D-03 | Price changes | Owners can change room prices, but price changes do not affect guests who have already booked. Existing bookings retain their original price. | Stakeholder Session 1 |
| D-04 | Payment requirement | Payment is mandatory and must be completed by card or PayPal. No booking is created or confirmed without successful payment. Payment at the hotel is not allowed. | Stakeholder Session 1 |
| D-05 | Mandatory registration | Users must register before making a booking. | Stakeholder Session 1 |
| D-06 | Required user information | First name, last name, and email address are mandatory. Phone number is optional. A billing address is requested only if the guest asks for an invoice. Nationality and copies of identity documents are not collected. | Stakeholder Session 1 |
| D-07 | Birthday information | Explicit user consent is required before collecting birthday information. Marketing emails may be sent only with the user's explicit consent. | Stakeholder Session 1 |
| D-08 | Guest cancellation policy | Guests can cancel free of charge at least 48 hours before arrival. If they cancel less than 48 hours before arrival, they are charged for the first night. | Stakeholder Session 1; clarified afterward |
| D-09 | Wheelchair accessibility | Wheelchair accessibility must be provided as a filter when searching for rooms. | Stakeholder Session 1 |
| D-10 | Accessibility standards | The software must support screen readers and keyboard navigation and comply with WCAG 2.1 Level AA. | Stakeholder Session 1 |
| D-11 | Owner cancellation policy | Owners can cancel bookings at least 14 days before arrival, provided they give a valid reason. The guest receives a full refund and is informed automatically. If fewer than 14 days remain, the owner must contact support instead of cancelling directly. | Stakeholder Session 1 |
| D-12 | Booking modifications | Guests may request booking changes under the applicable cancellation rules, including changes involving the payment method. Date or room-type changes are allowed until 48 hours before check-in; the current price applies to the changed booking. | Stakeholder Session 1 |
| D-13 | Modifiable booking details | The confirmed modifiable booking details are dates and room type (until 48 hours before check-in, at the current price). Payment-method changes are subject to the same applicable booking-change/cancellation rules. Whether the number of guests may also be changed requires checking the stakeholder notes. | Stakeholder Session 1 |
| D-14 | System availability | The system must be available 99.5% of the time each month. | Stakeholder Session 1 |
| D-15 | Maintenance window | Planned maintenance is allowed only on Tuesdays between 02:00 and 04:00. | Stakeholder Session 1 |
| D-16 | System failure notification | If the system goes down during booking, users must receive a message informing them that the booking was not completed. | Stakeholder Session 1 |
| D-17 | Displayed prices | All displayed prices must include taxes. | Stakeholder Session 1 |
| D-18 | Concurrent users | The system must support 3,000 simultaneous users during peak times. | Stakeholder Session 1 |
| D-19 | User growth | The platform currently has about 3,000 users and is expected to grow to about 10,000 users within one to two years. | Stakeholder Session 1 |
| D-20 | Refund policy | Guests receive a full refund when cancelling at least 48 hours before arrival. Cancellations less than 48 hours before arrival incur a first-night charge. | Stakeholder Session 1; clarified afterward |
| D-21 | Temporary room hold | A room is temporarily held for 30 minutes after the user presses the Pay button. This temporary hold is not a confirmed booking. | Stakeholder Session 1 |
| D-22 | Expired room hold | If the 30-minute hold expires without successful payment, the room becomes available for other users to book. | Stakeholder Session 1; clarified afterward |
| D-23 | Promotional codes | Users can apply promotional codes during the booking process. | Stakeholder Session 1 |
| D-24 | Complaint handling | Users can submit complaints through the user portal. Owners have 14 days to respond to complaints. | Stakeholder Session 1 |
| D-25 | Reviews | Owners are not obligated to respond to guest reviews. | Stakeholder Session 1 |
| D-26 | Concurrent booking requests | When multiple users request the same available room, the request that reaches the system first receives priority. | Stakeholder Session 1 |
| D-27 | Payment failure | If payment fails, the user's entered data is saved for 30 minutes so they do not have to enter it again when retrying payment. | Stakeholder Session 1 |
| D-28 | Discrimination reporting | Users must be able to report incidents of discrimination. | Stakeholder Session 1 |
| D-29 | Personal-data retention | Accounts with no booking are deleted after 2 years. Personal data of guests who have made a booking is retained for 3 years. | Stakeholder decision clarified in professor feedback |
